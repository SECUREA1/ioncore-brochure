What is Sentinel Multi‑Cam AI?

A desktop/edge application that ingests up to 8 camera feeds and performs real‑time recognition — people, faces (with unknown bucketing), objects (with color pooling), and vehicles. It logs human‑readable events (who picked up what, where it was placed, for how long), supports instant last‑location recall, and provides review queues for faces, people, and vehicles.

  • Face recognition with unknown re‑ID buckets
  • Shirt color sampling near detected heads
  • Object color pooling and custom labels (per object or color)
  • Vehicle DB with perceptual hash, snapshots, and attributes
  • Spot‑locks to suppress repeat re‑tagging in the same location
  • Auto‑place timeout for held items
  • Tuning overlay for thresholds, idle %, NMS, and more

Architecture at a glance

  • CoreOpenCV + YOLOv3 (objects), face_recognition (dlib) for faces
  • UITkinter desktop app; multi‑cam worker threads
  • StorageLocal JSON/NPY + snapshots; optional external DB
  • PerfCUDA when available; otherwise optimized CPU
  • ExtensibilityWebhooks; custom labels; color pooling per label

Key features

People & Faces

Identify known faces, consistently bucket unknowns, and capture shirt color near the head for rapid description and re‑ID.

  • Known/Unknown persons with last‑seen recall
  • Shirt color hex + basic color name
  • Cooldowns to avoid event spam

Objects & Actions

Per‑object state machine (Placed → Picked Up → Held → Placed) with durations and color‑pooled naming.

  • Custom labels for object or (object+color)
  • Auto‑place after idle timeout
  • Spot‑locks to suppress duplicate re‑tags

Vehicle Registry

Local vehicle registry keyed by perceptual hash; store make/model/plate/nicknames and snapshots.

  • Color detection & hex
  • Recent sighting timeline
  • Snapshot viewer

Notifications

Subscribe to specific people, objects, or vehicle labels. Route through your preferred channel.

  • Pushover, Telegram, Twilio SMS/MMS, Webhooks
  • Optional built‑in media host for MMS
  • Global cooldown to prevent floods

FAQ

Do I need a cloud DB?

No. Everything works locally out of the box. A cloud DB is optional for centralizing logs, analytics, or multi‑site access.

How are notifications handled?

Choose your channel (Pushover, Telegram, Twilio, or Webhook) and subscribe to specific people, objects, or vehicle labels. Optional built‑in media host helps with MMS images.

What about privacy?

It’s local‑first. You decide what to store, for how long, and whether to sync anything to the cloud. Tuning options and logs are auditable.

Can I change the detection models?

Yes. The roadmap includes pluggable model backends. Today’s default is YOLOv3 for objects and face_recognition for faces.
